# 개발 컨벤션

이 디렉터리는 Pizza 저장소에서 반복적으로 적용하는 코드 및 테스트 작성 기준을 기록합니다.
개별 기능의 정책이나 특정 PR의 구현 세부사항이 아니라, 새로운 코드를 작성하고 리뷰할 때 공통으로 사용할 판단 기준을 다룹니다.

## 문서 목록

| 주제 | 문서 |
| --- | --- |
| 테스트 계층, 기술 스택, mock과 주석 사용 기준 | [테스트 작성 원칙](testing.md) |
| AWS 리소스 이름과 공통 태그 규칙 | [AWS 리소스 네이밍 컨벤션](aws-naming-convention.md) |
| 브랜치, merge, 릴리스와 커밋 운영 기준 | [Git 브랜치·릴리스·커밋 운영 가이드](git-workflow.md) |

## 적용 원칙

- 새 코드와 새 테스트부터 적용하며 관련 없는 기존 코드를 일괄 변환하지 않습니다.
- 기능 영역의 기존 구조와 충돌하면 해당 영역의 일관성을 먼저 검토합니다.
- 규칙을 기계적으로 적용하기보다 테스트의 목적과 실패 시 전달할 정보를 우선합니다.
- 특정 기능의 상태, 메시지, 재시도 횟수와 같은 정책은 해당 기능 문서에서 관리합니다.
- 장기적인 설계 선택과 대안 비교가 필요한 결정은 [ADR](../adr/)로 기록합니다.

새 컨벤션 문서를 추가하면 이 문서와 상위 [문서 지도](../README.md)를 함께 갱신합니다.
